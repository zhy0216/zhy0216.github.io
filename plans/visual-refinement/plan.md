# Portfolio visual refinement

## 意图

用户通过 `$auto-dev 视觉上再提升一下` 要求继续提升当前作品集的视觉完成度，并自动启动实现。任务属于现有前端的视觉迭代：以首页为重点，让黑白、钴蓝和 Three.js 组成的现有语言更清晰、更有层次，并修正博客入口和阅读页面中影响观感的排版问题。沿用现有作品、文案事实与多页面结构；以实际浏览器截图判断改进是否成立。

## 仓库事实与现状

- 分析基线：`471390b`，开始时工作区干净。
- React 19、Vite 6、Three.js，样式由普通 CSS 管理；字体已使用本地 Manrope Variable 与 DM Mono，无须引入字体服务或 UI 框架。
- `src/App.jsx` 包含 `Nav`、`Hero`、`OrbitalScene`、`About`、`Work`、`ProjectArt`、`Blog`、`Lab`、`Contact`、`EndlessFooter`。`src/index.css` 同时管理基础样式、首页、仓库展示和博客。
- `src/blog/BlogPage.jsx` 实现博客列表、文章页和导航。`src/blogs.js` 从 `blogs/*.md` 提供文章数据、背景图和代码块；当前有两篇文章，首页最多展示三篇。
- `src/RepositoryField.jsx` 实现仓库筛选、图形场景和选中项读数，数据及离线快照来自 `src/githubRepositories.js`。
- 六个 Vite HTML 入口为 `/`、`/blog/` 和 `/work/{zebra,starwreck,better-trigger,sangota}/`。四个项目页也先导入 `src/index.css`，再导入各自 CSS，因此改共享样式后必须检查它们。
- 仓库没有 README、仓库内 AGENTS.md、lint、typecheck 或 test 脚本；按会话中的 AGENTS.md 检索规则工作。语义索引缺失后使用精确搜索确认代码位置，没有创建索引。
- `package.json` 只有 `dev`、`build`、`preview`。`npm run build` 已通过，61 个模块，六个入口均成功输出，没有构建警告。当前改动不需要升级依赖或建立测试框架。

### 已观察到的视觉问题

在本地生产预览中检查了 1440×1000 桌面和 390×844 手机视口；截图使用 `prefers-reduced-motion: reduce` 以固定画面，GitHub API 请求被阻断以使用已有快照。已查看首页首屏、作品区、首页文章区、博客列表首屏、文章首屏。此次抽查没有捕获到页面 JavaScript 异常；390px 首页没有横向溢出，这不是全站回归结论。

## 目标 / 非目标

### 目标

1. 首页首屏、作品卡片、文章入口呈现可直接看出的视觉提升，而非仅修改几个颜色值。
2. 保持 Manrope / DM Mono、深色与纸白区块、钴蓝强调和几何图形的品牌连续性，通过构图、字号、字重、留白和边框建立层级。
3. 桌面、平板和手机均有经过调整的布局；正文和交互容易辨认，键盘焦点与触控状态清楚。
4. 博客文章数量变化时布局完整，文章阅读和代码块维持清晰。
5. 六个入口、四个项目链接、首页锚点、邮件入口、仓库筛选和文章复制继续工作；普通动画、减少动画和 WebGL 不可用状态均可浏览。

### 非目标

- 不重写四个项目详情页的视觉叙事或内部 Three.js 场景；仅对共享样式带来的回归做必要修正。
- 不新增项目、文章、履历、服务能力或未经证实的状态与统计。
- 不改变 GitHub 数据获取、邮件保护、Markdown 渲染语义、路由或无限页脚的产品行为；仅在本次视觉或响应式变化造成问题时做最小关联修复。
- 不引入 UI 框架、动画库、远程字体、生成图片或新的大资源，不做无关性能、工程化或依赖升级。
- 本流程提交计划并启动本地执行；不 push、不发布。`master` 的 push 会触发现有 GitHub Pages 工作流，发布不属于本次请求。

## 方案

### 1. 统一视觉基准

- 以黑色、纸白、钴蓝为主，减少相互竞争的细节。钴蓝用于重点文字、主行动与选中态；次要线条和装饰降低权重。
- 在 `src/index.css` 的现有位置整理需要调整的令牌与规则。优先使用少量共享字号、间距、表面和文字颜色变量，避免在文件末尾堆叠大量覆盖或做无关 CSS 拆分。
- 显示标题的字距以约 `-.045em` 至 `-.025em` 为起点按画面调整，字号使用 `clamp()`，行高支持多行；不能机械地给所有标题套一个尺寸。显示标题与正文使用不同字重，正文优先 400。
- 首屏说明在手机至少 15px、桌面约 16–18px；一般说明约 14–16px，导航和可交互标签约 11–12px。次要装饰编号可以更小，但不能用同样规格承载主要信息。
- 有信息意义的普通文字目标对比度至少 4.5:1，大号文字至少 3:1；蓝色应分别验证深、浅底使用效果。
- 保持细线网格和克制的几何语言，通过表面明暗与间距体现层次。作品独有的蓝紫、游戏画面与地图资源继续保留。

### 2. 首页首屏与内容节奏

- 调整 `Nav` / `Hero` 的标题宽度、换行、首屏留白及 CTA 布局。桌面文字和球体各有清楚的构图区域；手机说明、按钮与图形不能互相遮挡，矮屏允许自然增长与滚动。
- 优先用 CSS 调整 `.hero-orb-wrap`、遮罩与图形裁切；确有必要时小幅调整 `OrbitalScene` 的视角或材质。保留现有资源清理、像素比限制、减少动画与 WebGL 失败路径，不能增加常驻场景或把重要内容画进 canvas。
- 对 `About`、`Work`、首页 `Blog`、`Lab` 标题和 `Contact` 做同一套排版精修。保留内容顺序和原有四张作品图，调整大、小作品卡的视觉平衡、图像比例、说明行长和 CTA 位置。
- 首页文章使用内容自适应网格；当前两篇时占满内容区，未来一篇、三篇时也没有空槽或失衡。需要区分文章视觉时复用已有 `backgroundImage` 元数据，有图与无图都必须完整，不以随机图片补位。
- 让可点击作品图、文字入口、导航、卡片在 hover 和 `:focus-visible` / `:focus-within` 下有一致反馈；触摸设备不依赖 hover 才能理解或进入内容。移动菜单按钮达到约 44×44px，关闭后的菜单不能留下不可见的可聚焦项。
- 对 About 现有 hover 说明的处理以可读性为准，可以改为常显；保留的补充内容必须同时可被键盘和触控访问。
- 新增过渡限制在颜色、透明度和小幅 transform，通常 160–280ms；减少动画时静态展示内容，不引入滚动劫持或延迟展示首屏。

### 3. 博客列表与阅读一致性

- `BlogIndex` 与首页文章区共享已经确定的排版尺度；修正博客 hero 过窄的可用文本宽度，桌面不再出现目前孤立的 “the” 与 “edge” 行。1440px 宽时希望第一屏底部能露出列表或列表标题，而不是完全被 hero 占满。
- 列表随实际文章数和视口调整，标题大小根据卡片宽度控制。两篇时可采用两列或清楚的通栏文章行，三篇及以上应自然换行；所有边框在换行后仍合理。
- 用日期、阅读时长等真实字段组织卡片信息，替换 `MARKDOWN / BUILT AT DEPLOY TIME` 这类不帮助读者选文章的实现说明。
- 微调文章 hero 与正文开始处的节奏、标题对比、背景遮罩、标签、正文和侧栏。保留当前文章标题平衡换行、正文衬线 h2/h3、代码块横向滚动和复制按钮、已有文章内交互示例的运行方式。
- 同时检查 `css-z-index-is-a-tree`（无背景图）与 `postgresql-speculative-insertion`（有背景图），不能只根据一篇文章做样式。

### 4. 浏览器复核与交付

- 先完成统一视觉实现，再由独立验证任务检查最终组合效果、修正明确问题并记录证据。
- 不为静态样式编写镜像实现的单元测试或引入截图测试框架。使用现有构建和临时浏览器脚本检查真实页面与交互；浏览器依赖不进入项目依赖。
- 在计划目录内交付 `verification.md`，列明视口、页面、普通/减少动画/无 WebGL 状态、检查结果和遗留限制；精选前后对照截图可放在 `plans/visual-refinement/evidence/`。报告中的截图路径应为仓库内相对路径，并区分真实检查与未测项目。

## 执行偏好

- 当前宿主：Codex；`default_agent: codex`，来源为宿主默认。
- 用户没有指定全局模型、推理强度或单任务 agent；todo 使用 `agent: inherit`。
- 按分发规则，两项 `medium` 任务均解析为 Codex / `gpt-6-astra` / `xhigh`；这是难度映射，不是用户模型覆盖。
- auto-dev 协调器使用 Codex / `gpt-6-astra` / `high`，启动参数显式包含 `--dangerously-bypass-approvals-and-sandbox`。执行器仍逐项读取难度和偏好。
- 本机 `codex --help` 已确认支持上述 CLI 参数，模型元数据已确认 `gpt-6-astra` 支持 `high`、`xhigh` 和 `max`；不需要 OpenCode。
- Herdr 环境检查已通过；提交计划后在当前 pane 右侧创建同级 pane，保留仓库根目录与当前焦点，自动发送 `$herdr-finish-plan visual-refinement`。

## 校验

### 命令

- 初始安装按需运行 `npm ci`（已有可用依赖时无需重复安装）。
- 每个实现提交与最终集成后运行 `npm run build`、`git diff --check`。
- 浏览器预览运行 `npm run preview -- --host 127.0.0.1 --port <空闲端口> --strictPort`；端口来自实际启动结果，不关闭用户现有服务。
- 任务中发生新的 JSX / CSS 修改后再构建并复查受影响页面。不要声称运行不存在的 lint、test 或 typecheck 脚本。

### 可验收结果

- 首页在对照截图中能看出标题与球体构图、说明可读性、作品卡片和内容节奏的改进；不以增加装饰数量作为完成标准。
- 手机首屏说明计算字号至少 15px，主要操作和长文本没有遮挡；页面整体 `scrollWidth <= clientWidth + 1`，代码块允许在自身容器内部横向滚动。
- 1440px 博客 hero 标题没有目前四行拥挤排版和孤立单词；当前两篇文章不再留下空白第三列，未来数量变化能合理布局。
- 重要文字和蓝色交互符合上述对比目标；键盘焦点可见，关闭的移动菜单不接收焦点，减少动画模式不隐藏内容。
- 所有原有链接、文章功能、仓库筛选与邮件入口通过复核；验证邮件只检查入口，不实际发送信息。
- `npm run build` 与 `git diff --check` 通过；有一份包含真实浏览器检查和精选对照画面的交付报告。

## 风险与假设

- “再提升”没有新的参考图或方向限定，采用对当前设计的连续精修，重点是首页，并覆盖与首页共用的博客视觉。这个次要假设不会阻止启动实现。
- `src/index.css` 被所有入口使用，修改全局 `body`、字体、颜色或基础按钮规则影响面较广；尽量局部化变化并对四个项目页做回归。
- 现有项目图和无限页脚有较多动画。初始截图使用减少动画只用于比较静态构图，最终必须另测普通动画，不能用静态截图替代运行检查。
- 球体效果因 GPU 与 WebGL 可用性不同而变化；视觉依赖的层次应有 CSS 退化版本，不能通过提高粒子数或像素比弥补构图。
- 一、二、三、四篇文章的验证使用临时数据或临时浏览器脚本，不能创建假文章进入交付。
- 本计划属于明确视觉需求，不进入无 prompt 的全仓库探索模式；没有需要本轮排队的 roadmap 事项，也没有阻塞方案的开放问题。
