# 首页与博客视觉精修

优先级：P1。执行选择：继承 `README.md`，当前解析为 Codex / `gpt-6-astra` / `xhigh`。

先完整阅读 [../plan.md](../plan.md)。任务条目共享 `src/index.css` 和首页组件文件，作为一个独立实现任务，在一个 worktree 内完成并形成一个最终 commit。

## T1 · 确定画面基线与视觉尺度

**要做什么**

- 在改动前启动本地预览，捕获首页首屏、作品区、首页文章区和博客首屏的 1440×1000 / 390×844 基线。使用减少动画固定对照，另外打开普通动画确认原始表现；不能将截图中的粘性导航或滚动状态误判为布局缺陷。
- 沿用黑白、钴蓝、Manrope / DM Mono 和几何图形，调整 `src/index.css` 的现有排版与间距规则。显示标题放松过紧字距，正文与交互信息提高字重、字号和对比，深浅背景各自保持清楚的蓝色状态。
- 在原有 CSS 区块内修改需要变化的样式，保持清楚的作用范围；不做无关架构重构，不在尾部积累一批互相覆盖的规则。

**预计修改的文件**

- `src/index.css`
- `plans/visual-refinement/evidence/`（精选原始截图，名称包含 before 与视口；只提交必要画面）

**验收条件**

- 有可供后续复核使用的修改前画面，截图文件可被任务 02 从本提交读取。
- 共享显示标题、正文、辅助标签、按钮和间距形成一致尺度；有信息意义的普通文字目标对比至少 4.5:1，大号文字至少 3:1。
- 字体继续使用已有本地资源，项目依赖与锁文件无需改动。

**前置依赖**：无。

## T2 · 精修首页首屏、作品与内容区

**要做什么**

- 在 `Nav`、`Hero` 和对应样式中调整首屏标题宽度、字号、换行、球体裁切和 CTA 位置；主标题、说明和主行动一眼可辨。去掉首屏说明 `.72em` 再缩小的效果，手机计算字号至少 15px。
- 优先调整 `.hero-orb-wrap`、遮罩和网格构图；必要时小幅改 `OrbitalScene` 的视角或材质，保持已有 WebGL 失败路径、减少动画模式、资源清理和像素比限制。
- 精修 `About`、`Work` / `ProjectArt`、`Blog`、`Lab`、`Contact` 的层级、对齐和留白；保留四种作品专属画面，提高作品说明和入口的可读性，利用表面明暗、细边框与小幅交互反馈丰富层次。
- 首页文章网格依据实际内容自适应，一篇、两篇、三篇都能合理填满；保留最多三篇的现有取数规则。如使用文章图像，只复用已有可选背景图元数据，无图的文章也要形成完整设计。
- 让卡片、按钮、导航的 hover 与键盘焦点反馈一致，手机入口可直接理解。移动菜单按钮约 44×44px，关闭菜单不留下不可见的可聚焦项；About 补充说明可选择常显，不能只靠鼠标悬停读取。
- 新的过渡尊重减少动画偏好；现有无限页脚和仓库数据行为保持原有作用，必要的标记调整不得改变筛选或链接语义。

**预计修改的文件**

- `src/App.jsx`
- `src/index.css`
- `src/RepositoryField.jsx`（仅当展示语义或焦点反馈需要少量标记调整；数据与状态逻辑不在范围内）

**验收条件**

- 1440×1000、768×1024、390×844 下，首屏和作品区都有清楚的视觉改善；在 320×740 补查长文本和 CTA，无相互遮挡或页面级横向溢出。
- 手机说明字号至少 15px；首屏高度不足时允许自然滚动，不用固定高度裁掉文字或操作。
- 四个作品仍指向原有 `/work/` 页面，项目图形仍各有辨识度；首页文章当前两篇不再留下空白第三列。
- 首页锚点、移动菜单、邮箱入口、仓库筛选可用，键盘焦点可见。仅检查邮箱入口，不发送邮件。
- 普通动画、减少动画和模拟 WebGL 创建失败都能看到完整重要内容、使用链接；无新增未捕获异常。

**前置依赖**：本文件 T1。

## T3 · 调整博客列表与文章阅读层级

**要做什么**

- 在 `BlogIndex` / `.blog-hero-copy` 中共同调整标题可用宽度、字号与行高，避免当前 1440px 宽度下四行、孤立单词和拥挤字距；让文章列表更早进入视野。
- 在 `BlogCard` 与 `.blog-page-grid` 中适配一、二、三、四篇内容，卡片标题按实际列宽调整；日期、标签、摘要、阅读入口形成明确顺序，处理换行后的边框。
- 用读者有用的真实信息替换 `MARKDOWN / BUILT AT DEPLOY TIME`；可使用已有日期、篇数和阅读时长字段，不编造数据。
- 微调 `BlogArticle` 的标题、背景遮罩、正文开始位置、正文行长和侧栏。保留已有平衡换行、衬线 h2/h3、代码复制、代码块内部滚动和文章交互示例。
- 同时检查 `css-z-index-is-a-tree` 与 `postgresql-speculative-insertion`，有图和无图文章均成立。

**预计修改的文件**

- `src/blog/BlogPage.jsx`
- `src/index.css`

**验收条件**

- 桌面博客首页标题形成有意图的两到三行排版，没有当前孤立的 “the” / “edge” 行；当前两篇文章完整利用内容宽度。
- 临时模拟一、三、四篇列表仍有合理布局，不提交假文章或为测试修改正式文章数据。
- 两篇实际文章在桌面和手机可读，背景不降低标题可辨认度；复制、返回与侧栏链接正常，代码块不撑宽整页。

**前置依赖**：本文件 T1、T2 的视觉尺度与首页实现。

## T4 · 构建与实施自检

**要做什么**

- 运行 `npm run build`、`git diff --check`，在生产预览中走查首页、博客列表、两篇文章和四个项目详情入口。
- 检查共享 CSS 是否改变项目页的标题、按钮和布局，只修复本轮造成的明确回归。
- 交付简短实施说明和基线截图列表，供任务 02 复核。不要把普通静态样式拆成镜像实现的单元测试，不新增浏览器依赖到项目。

**预计修改的文件**

- 本文件 T1–T3 已涉及的文件。
- 四个项目的 `src/{zebra,starwreck,better-trigger,sangota}/*.css`，仅限有证据的共享样式回归，默认无需修改。

**验收条件**

- 两个仓库校验命令通过，六个入口都能打开；真实浏览器检查与任何限制在最终汇报中清楚标出。
- 最终只有当前视觉范围相关文件、必要的精选基线截图；保留原有业务文案事实、资源、URL 和文章内容。
- 一个最终 commit，可以被协调器复核和集成；任务 02 应从此提交已集成的基线开始。

**前置依赖**：本文件 T2、T3。
